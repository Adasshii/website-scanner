</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scans.pages (JSONB) → prospects update | Data derived from an untrusted site is persisted; writes are parameterized Supabase `.update()` calls only |
| re-scan → existing prospect state | A later scan must not be able to erase a human's manual-review contact/classification |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Tampering | reconcile overwriting a reviewed contact | high | mitigate | Fill-only-when-null guard: a done prospect with a non-null contact_email is written scan_status-only, never a contact field (orchestrator re-scan directive) |
| T-05-08 | Injection | extracted email/text into the DB | medium | mitigate | Only parameterized `.update()` writes; no string interpolation into any query; email length already bounded (254) in aggregateContacts |
| T-05-09 | Repudiation | which scan produced the contact | low | accept | latest_scan_id already ties the prospect to the producing scan (migration 013); no extra provenance needed this phase |
</threat_model>
