<objective>
Build the release mechanism: `lib/triage-release.ts` (select the worst-ranked eligible,
un-released prospects up to the hard ceiling and mark `scan_released_at` — TRI-08 cutoff +
TRI-09 ceiling, enforced independently) and `app/api/admin/release-prospects/route.ts` (the
D-11 admin-triggered, service-role release action behind the existing admin auth gate).

with a maximally permissive cutoff. The worst-N selection, ceiling, and "released never
re-releases" rule are the load-bearing correctness properties, so they get their own
integration suite against local Postgres.
Output: `lib/triage-release.ts`, its integration suite, and the release API route.
</objective>
