<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| triage script → arbitrary prospect websites | Bulk outbound fetch of untrusted third-party homepages |
| triage script → prospects table | Service-role per-row write of triage_score/triage_checked_at |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-blast | Reputational / blast-radius | batch loop | medium | mitigate | `BATCH_SIZE` concurrency cap + `BATCH_DELAY_MS` inter-batch spacing (D-12); honest UA + robots.txt check inherited from lib/triage-fetch.ts; runs off the production IP (D-10) so it cannot fingerprint the live scanner's Railway IP |
| T-03-contain | blast-radius / containment | triage script | high | mitigate | Triage touches only `triage_score`/`triage_checked_at` via `.update().eq("id")`; it never calls the scanner service, Resend, or the public scan path — an outreach/triage failure cannot degrade the live public scanner (project blast-radius constraint) |
| T-03-notnull | Tampering / data integrity | per-row write | medium | mitigate | `.update(...).eq("id", id)` never `.upsert()` (Pitfall 3, `country` NOT NULL); per-row try/catch skips one bad row without aborting the run |
| T-03-SSRF | Tampering / Information Disclosure | fetch path | high | mitigate | Delegates to lib/triage-fetch.ts's per-hop `validateUrlSafe()` (built + tested in Plan 02); the script adds no second unguarded fetch primitive |
| T-03-SC | Tampering | npm installs | high | mitigate | No installs; TRI-01 grep gate proves no browser/DOM/AI import in the script |
</threat_model>
