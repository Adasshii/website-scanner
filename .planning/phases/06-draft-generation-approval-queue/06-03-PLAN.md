<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanned website content → prompt text | Issue titles and business names originate from a third party's page and are interpolated into a model prompt |
| model output → outgoing message | Anything the model returns is a candidate for a message sent to a stranger |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-PI | Tampering | Scanned-site text interpolated into `buildDraftPrompt` | low | mitigate | The prompt's output contract forbids the model from writing any legal or disclosure text of its own, so injected instructions cannot fabricate a compliance notice; the notice is appended by `appendArticle14Notice` after generation. Every draft still passes the per-message human gate (QUE-01) before anything can send |
| T-06-A14 | Repudiation | Article 14 notice omitted or paraphrased | high | mitigate | This plan: the notice is a code constant appended after generation (D-6-12), never requested from the model; a test asserts the prompt does not contain it and `appendArticle14Notice` is idempotent |
| T-06-SSRF | Tampering / Information Disclosure | URL rendered inside the draft body | low | mitigate | `buildDraftPrompt` receives the report URL as a parameter constructed by the caller from `BASE_URL` + scan id; this module never accepts or embeds a URL taken from scanned content |
| T-06-KEY | Information Disclosure | Gemini credential | high | accept | No credential is read in this plan — both modules are pure and grep-gated against `process.env` |
| T-06-REJ | Tampering | Rejected prospect re-drafted | high | accept | Out of scope here; the read gate lands in 06-05 |
</threat_model>
