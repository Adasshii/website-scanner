<objective>
Build the queue's data layer and its admin API: list pending drafts with their evidence, edit,
approve, reject, regenerate, and manually generate for a prospect that has no draft yet.

Purpose: QUE-01, QUE-02, QUE-03, and the state-transition half of D-6-13 through D-6-16. The route
stays thin and the logic lives in a library module, matching this repo's existing split
(`app/api/admin/shortlist/route.ts` over `lib/triage-candidates.ts`), so the transitions can be
integration-tested against a real Postgres without constructing HTTP requests.

This plan is also where the phase's hardest boundary is enforced: approve stops. It writes three
columns and nothing else. No dispatcher, no send queue, no suppression check, no unsubscribe
header, no lifecycle advance. All of that is Phase 8 and Phase 7, and Phase 8's channel is still
undecided.

Output: `lib/outreach-queue.ts`, its integration suite, and `app/api/admin/outreach/route.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to admin API | Only the shared admin secret separates the queue from the public internet |
| admin editorial input to database | Free-text subject and body written straight into a row that will later become an outgoing message |
| editorial reject to compliance suppression | Two adjacent concepts that must not be conflated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-AC | Spoofing / Elevation of Privilege | `/api/admin/outreach` GET, PATCH, POST | high | mitigate | The same `x-admin-secret` comparison against `ADMIN_SECRET` used by every existing admin route, present in all three handlers, grep-gated to three occurrences; no new auth mechanism is introduced (ASVS V2, V4) |
| T-06-VAL | Tampering | Draft subject and body free text | medium | mitigate | `applyDraftEdit` trims, rejects empty, and enforces named maximum lengths before any write (ASVS V5). Input is single-tenant and operator-supplied, so the control is bounds and emptiness, not sanitisation |
| T-06-REJ | Tampering | Rejected prospect resurrected | high | mitigate | `rejectDraft` writes `prospects.lifecycle_state = 'rejected'`, the value 06-05's eligibility gate reads on every subsequent scan-complete; integration-tested on both sides |
| T-06-SUP | Tampering | Reject wrongly writing a compliance suppression entry | medium | mitigate | Grep gate asserts this module never imports the suppression layer, and an integration test asserts no suppressions row exists after a reject. CMP-06 entries are hard to reverse by design, so an editorial mistake must not create one |
| T-06-SEND | Repudiation | A draft leaving the queue before the send phase and its audit record exist | high | mitigate | `approveDraft` writes three columns only; grep gates assert no `sent_at` write and no import of the email module or scanner client. Phase 8 owns dispatch and its channel is undecided (D-6-16, D-6-R2) |
| T-06-BULK | Elevation of Privilege | One action approving many drafts, bypassing the per-message human gate | high | mitigate | Every function and handler takes exactly one id; a grep gate asserts no collection-of-identifiers parameter exists in the route (QUE-05, D-6-R1) |
| T-06-PI | Tampering | Prompt injection surfacing in a listed draft | low | mitigate | Model output is only ever rendered for review; nothing acts on it automatically |
| T-06-SSRF | Tampering / Information Disclosure | Report URL in a listed row | low | mitigate | `buildReportUrl` is code-constructed from `BASE_URL` and the scan id |
| T-06-KEY | Information Disclosure | Gemini credential used by regenerate | high | accept | Controlled in 06-02 and 06-04; this plan reads no credential directly |
