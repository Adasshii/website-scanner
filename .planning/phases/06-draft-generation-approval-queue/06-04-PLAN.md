<objective>
Build the single function that turns a completed scan into a reviewable draft: prompt in, guarded
model output out, Article 14 notice attached, or null.

Purpose: DRA-01, DRA-02, DRA-03 and DRA-05 all land on this one function. It is also the first
time this codebase calls an external AI API from the Next.js/Vercel side — every prior Gemini call
lives in the always-on Railway service — so it establishes the pattern: plain `Promise.race`
timeout per the existing convention, dependency-injected client seam for deterministic tests, and
never throwing into the caller.

Output: a root-level `@google/generative-ai` dependency and `lib/draft-generator.ts` with full
unit coverage that never touches the network.
</objective>

  <behavior>
    - With an injected generate that returns a body containing the metric's `displayValue`, the result is non-null and its `body` ends with the locale's Article 14 notice.
    - With an injected generate that returns a body OMITTING the `displayValue`, the result is `null` and an error is logged.
    - With an injected generate that returns a body where the number was rounded (`"4 seconds"` when `displayValue` is `"4.3"`), the result is `null`.
    - With an injected generate that returns `null` (simulating timeout), the result is `null` and nothing throws.
    - With an injected generate that throws, the result is `null` and nothing propagates to the caller.
    - When the generated body already contains the report URL, the URL appears exactly once in the final body.
    - When the generated body omits the report URL, the final body still contains it (appended on its own line).
    - For a prospect whose country is `"NL"`, the final body ends with the Dutch notice; for an unmapped country it ends with the English one.
    - `generateDraft` returns a `subject` produced by `buildDraftSubject`, never by the model.
    - The whole test file runs with no network access and no `GEMINI_API_KEY` present.
  </behavior>
  <action>
    Create `lib/draft-generator.ts`.

    Export `buildReportUrl(scanId)` returning the hosted report address, reusing the same
    `BASE_URL` expression `lib/email.ts` already defines (read it and mirror it; do not invent a
    second default host). This is the DRA-03 link and it is always code-constructed from the scan
    id — it never accepts a URL taken from scanned page content.

    Export `generateDraft(input, deps = {})`. `input` carries the prospect row fields needed
    (`name`, `domain`, `country`, `contact_email`) and the scan row fields (`id`, `scores`,
    `summary`, `pages`). Steps, in order:

    1. Resolve locale via `localeForCountry(input.prospect.country)`. Use the prospect's country,
       never the scan row's locale field — bulk scan rows do not carry one and it means a different
       thing (RESEARCH Pitfall 4).
    2. Resolve the top three issue titles through the existing localisation helpers in
       `lib/i18n-helpers.ts` for that locale before passing them to the prompt builder, so a Dutch
       draft never quotes English issue text (RESEARCH Pitfall 7).
    3. Compute the verdict with `computeVerdict` from `lib/scoring.ts` rather than reading the
       stored summary verdict, so all three surfaces derive it from the one function (DRA-06).
    4. Call `selectCitableMetric`. If it returns null, return null — no evidence, no draft.
    5. Build the prompt with `buildDraftPrompt`.
    6. Call `deps.generate ?? defaultGeminiGenerate`. The default implementation lazily constructs
       the SDK client from `process.env.GEMINI_API_KEY`, returns null immediately if that variable
       is absent, uses the same model name the scanner service already uses, and wraps the call in a
       local `Promise.race` timeout of 45000 ms resolving to null, with a `.catch(() => null)` tail.
       Follow the codebase's existing wrapper convention rather than the SDK's own request-timeout
       option; mixing the two makes failure behaviour inconsistent for the next reader.
    7. If the raw result is null or blank, log with a `[draft]` bracketed prefix and return null.
    8. Verbatim guard: if the raw body does not contain `metric.displayValue` as a substring, log and
       return null. Treat it exactly like a generation failure — a draft that silently fails DRA-02
       is worse than no draft, and regenerate is the recovery path.
    9. Report link: if the raw body does not already contain the report URL, append it on its own
       line. This asymmetry with step 8 is deliberate and must be commented — a wrong number is
       unrepairable in code, a missing link is repairable, so one fails closed and the other is
       repaired.
    10. Append the notice with `appendArticle14Notice(body, locale)` inside this function so no
        caller can produce a draft without it.
    11. Return `{ subject: buildDraftSubject(domain, locale), body }`.

    The key is read from the server environment only. Do not introduce any client-visible variant of
    that variable name, and never log the value.

    Do not schedule any work to run after a response has been returned — this module is always
    awaited by its caller. Vercel's execution environment can freeze between the response and a
    deferred callback, so the always-on service's deferred-execution idiom does not transfer here.

    Write `lib/draft-generator.test.ts` first. Every test injects `deps.generate`; no test may
    construct the real client or read the API key.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanned website content → Gemini prompt | Business name, domain and issue titles originate from a third party's page |
| Gemini response → outreach_messages row | Model output becomes the candidate text of a message to a stranger |
| Next.js runtime → Google API | An API credential leaves the server on every generation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-PI | Tampering | Prompt injection via scanned page text reaching `buildDraftPrompt` | low | mitigate | No automated action is taken on model output: the result is written as a `draft` row that cannot leave the queue without a per-message human approval (QUE-01/QUE-05). The verbatim-metric guard additionally discards output that drifted from the code-supplied fact, which is the most likely observable effect of a successful injection |
| T-06-SSRF | Tampering / Information Disclosure | URL embedded in the draft body | low | mitigate | `buildReportUrl` constructs a same-origin URL from `BASE_URL` and the scan id only; no URL from scanned content is ever embedded, and this module performs no outbound fetch other than the Gemini call |
| T-06-KEY | Information Disclosure | `GEMINI_API_KEY` | high | mitigate | Read from the server environment only; grep gate asserts zero client-visible variants in this module; the value is never logged and the client is constructed lazily so a missing key degrades to `null` rather than throwing a stack trace containing config |
| T-06-A14 | Repudiation | Article 14 notice missing from a draft | high | mitigate | `appendArticle14Notice` is called inside `generateDraft`, so no call path can produce a draft without it; covered by a test |
| T-06-MET | Tampering | Model rounds or paraphrases the cited figure, breaking DRA-02 | medium | mitigate | `String.includes` guard on the exact `displayValue`; failure is treated as a generation failure with regenerate as the recovery path |
| T-06-REJ | Tampering | Rejected prospect re-drafted | high | accept | Not this module's concern — `generateDraft` is unconditional by design; the eligibility gate that reads `lifecycle_state = 'rejected'` lands in 06-05 |
| T-06-SC | Tampering | npm install of the Gemini SDK | high | mitigate | Package Legitimacy Audit verdict OK; already a production dependency of this repo; no `[ASSUMED]` or `[SUS]` package in this phase |
</threat_model>
