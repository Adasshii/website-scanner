<objective>
Add the manual "Generate draft" affordance to the Shortlist, covering both cases the automatic
scan-complete path deliberately or accidentally leaves without a draft.

Purpose: D-6-06 requires that named-person prospects stay out of the automatic queue but remain
clearable by judgement. RESEARCH open question 1 identified the adjacent gap and recommended folding
it in: a prospect with a perfectly usable generic email whose generation failed (a model timeout, or
a webhook call that never arrived) has no `outreach_messages` row, therefore never appears in the
Outreach tab at all, and therefore has no error state and no recovery path. It is the same button
with one extra condition, not new scope.

This also resolves the backfill question CONTEXT left to discretion: prospects scanned before this
phase shipped are handled by this same action. No one-off script is written, because at 10 to 50
prospects a week a script is more moving parts than the button that already has to exist.

Output: two derived fields on the shortlist payload and one link-style action in the Shortlist table.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to admin API | The session secret is the only credential on the generate action |
| prospects table to admin payload | Contact addresses are personal data and should not travel further than they need to |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-AC | Spoofing / Elevation of Privilege | POST to the admin outreach route from the Shortlist | high | mitigate | The action sends `x-admin-secret` from existing session state and the route re-checks it server-side; no new auth path is introduced |
| T-06-REJ | Tampering | Manual generation resurrecting a rejected prospect | high | mitigate | `generateDraftForProspect` in 06-06 checks `lifecycle_state` before creating a row, so this button cannot bypass an editorial rejection |
| T-06-PII | Information Disclosure | Contact addresses in the admin payload | medium | mitigate | This plan replaces the raw address with a derived boolean in the shortlist response, so the address is not sent to the browser at all; asserted by a test |
| T-06-DUP | Tampering | A second draft row created for a prospect that already has one | medium | mitigate | The action is hidden once `has_outreach_draft` is true, and `generateDraftForProspect` refuses server-side regardless of what the client sends |
| T-06-BULK | Elevation of Privilege | A multi-row generate action | high | mitigate | The action is per row and posts exactly one prospect id; no selection control is added to the Shortlist |
| T-06-PI | Tampering | Prompt injection via scanned content | low | accept | Same control as the automatic path: output lands as a reviewable draft, never an action |
| T-06-KEY | Information Disclosure | Gemini credential | high | accept | Generation happens server-side; no credential reaches the client |
</threat_model>
