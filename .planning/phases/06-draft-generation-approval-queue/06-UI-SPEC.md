# Phase 6 — UI Design Contract

> Visual and interaction contract for the new "Outreach" admin tab (D-6-01) and its
> expandable review panel. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope guard (inherited from 06-CONTEXT.md):** this contract governs ONE new admin tab
and its expanded row panel. It does not restyle `app/admin/page.tsx`'s Scans/Leads tabs,
does not touch the public scanner or `/report/[id]`, and proposes no design-system
overhaul. Every token below is lifted from what already exists in
`tailwind.config.ts` and `components/admin/*` — nothing new is introduced except where
explicitly marked.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind, matching `components/admin/*` conventions |
| Icon library | none — no icon usage in existing admin; this phase introduces none (a chevron for row-expand uses a CSS-rotated `▸` glyph or an inline SVG chevron, not a new dependency) |
| Font | `font-display` = `"DM Serif Display", Georgia, serif` (page/section headers only); default sans = `"Inter", "Helvetica Neue", Arial, sans-serif` (everything else) — both already declared in `tailwind.config.ts`, no change |

**Why no shadcn:** `components.json` does not exist in this repo. The admin surface is a
single-tenant internal tool built entirely as hand-rolled Tailwind (tables, pills,
buttons) with no component library anywhere in the codebase. Introducing one for a single
tab would be exactly the design-system overhaul the phase's scope guard forbids, and adds
a dependency (ladder rung 5) where reusing the existing `ShortlistTable`/`StatusPill`
pattern (ladder rung 2) already solves it. Confirmed by reading `tailwind.config.ts` and
`components/admin/*` directly — not asked, per the scope guard already fixing the answer.

## Spacing Scale

Declared values (must be multiples of 4) — identical to what `app/admin/page.tsx` and
`shortlist-table.tsx` already use throughout:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/pill internal gaps (`px-2 py-0.5` pill padding) |
| sm | 8px | Compact spacing between inline elements (`gap-2`, `mt-1`) |
| md | 16px | Table cell padding (`px-4 py-3`), default card padding |
| lg | 24px | Card padding (`p-6`), gap between draft/evidence columns in the expanded panel |
| xl | 32px | Vertical gap between major page sections |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: none. This is a desktop-only internal admin tool (secret-header auth, no
mobile field use case) — no 44px touch-target exception is needed.

## Typography

Matches the sizes/weights already in use across `app/admin/page.tsx` and
`components/admin/*`. This phase does not introduce a new type scale.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / meta | 12px (`text-xs`) | semibold (600) | 1.4 — pill text, table headers (uppercase, `tracking-wider`), timestamps, the Article 14 block's caption |
| Body | 14px (`text-sm`) | regular (400) | 1.5 — table cell text, draft subject/body textarea content, evidence pane stats |
| Section heading | 20px (`text-xl`, `font-display`) | semibold (600) | 1.2 — reserved for page-level headers only (already exists: "Adashi Admin"); the Outreach tab does NOT introduce a new heading level, it reuses the existing `TabButton` row |
| Score / stat emphasis | 24px (`text-2xl`) | **bold (700) — established exception** | 1.2 — score numbers, stat-card values. `StatCard` and the score `<span>` in `ScansTable`/`ShortlistTable` already use `font-bold`, not `font-semibold`. Documented here rather than forced to 600 so the new Outreach score column matches every existing score display pixel-for-pixel. |

Weight count is 2 in intent (regular 400 / semibold 600) with one documented pre-existing
exception (bold 700, scores only) carried forward for visual consistency — do not
introduce a fourth weight anywhere in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-gray-50` | Page background (`min-h-screen bg-gray-50`, already the admin shell) |
| Secondary (30%) | `bg-white` | Cards, table surface, the expanded row panel (`rounded-2xl shadow-card`) |
| Accent (10%) | `adashi-blue` `#006DFF` | Reserved for: active "Outreach" tab state, all links (domain links, "View full report" link), the primary Approve button, focus/checkbox accent, the Regenerate text-action link |
| Destructive | `red-600` `#DC2626` | Reject button (solid, confirms first), existing delete actions — no new red token introduced |

Accent reserved for: active tab pill, hyperlinks (`text-adashi-blue hover:underline`),
Approve button fill, Regenerate link-style action, range/checkbox `accent-adashi-blue`.
Never used for plain body text, pill backgrounds unrelated to status, or decorative
borders — matches how `adashi-blue` is used everywhere else in the admin today.

**Score color bands (reused, not new):** `>=80` → `text-green-600`, `>=50` →
`text-yellow-600`, else → `text-red-600`. Identical thresholds/classes to
`ScansTable`/`ShortlistTable` — the Outreach table's score column and the evidence
pane's overall-score badge both reuse this exact logic, not a re-derivation.

**Cited-number highlight (new, minimal):** the one specific number D-6-11 selects and
D-6-03 requires be "one glance" verifiable gets a shared highlight token —
`bg-adashi-electric/30 rounded px-1 font-semibold text-adashi-gulf` — applied both where
it appears inside the draft body text and where it repeats in the evidence pane. Same
token, both places, so visual matching (not re-reading) is how Joshua verifies it.

## Layout & Interaction Contract

*(Additional section beyond the template's fixed fields — the checker and executor need
this to implement D-6-01/02/03 correctly; kept prescriptive per the agent's own
instructions.)*

**Outreach tab, collapsed table (default = pending only, worst score first, D-6-04):**
Columns: `Domain` (linked, `_blank`), `Score` (color-banded, worst-first sort),
`Locale` (NL/EN text), `Status` pill (`DRAFT`/`EDITED`), relative timestamp, expand
affordance. Same `<table className="w-full text-sm">` / `border-b border-gray-50
hover:bg-gray-50/50` row shell as `ShortlistTable`. A small stat-card row above the table
(`grid grid-cols-2 sm:grid-cols-4 gap-4`, reusing `StatCard`) shows Pending / Approved /
Rejected / Total counts, mirroring `ShortlistTab`'s existing stat-card pattern exactly.

**Expandable row (D-6-02 — single-open, hard rule):** Clicking a row toggles a full-width
panel rendered as an additional `<tr>` with a single `<td colSpan={n}>` immediately below
it (standard expandable-row pattern, no new library). Expanding a second row
programmatically collapses the first — component state holds exactly one `expandedId:
string | null`, never a `Set`. This is the literal enforcement of QUE-05: there is no
code path in which two rows can be expanded, and therefore no view in which two Approve
buttons are simultaneously reachable.

Panel layout: `grid grid-cols-1 lg:grid-cols-2 gap-6 p-6` —
- **Left column (editable draft):** subject input (`text-sm`, bordered), body `<textarea>`
  (`text-sm`, `rows` sized to content, bordered, `focus:border-adashi-blue`), the fixed
  Article 14 block directly beneath the textarea (see below), then the action row
  (Save edit / Regenerate / Approve / Reject) as a `flex gap-3` row, Approve and Reject
  visually separated from Save/Regenerate by a bit more gap (`gap-3` within groups,
  `justify-between` between the edit-recovery group and the decision group) so Approve/
  Reject never look like just another pair of equal-weight buttons.
- **Right column (evidence pane, D-6-03):** overall score badge (color-banded, same
  token as the table), the consolidated DRA-06 verdict as body text, a two-item row of
  critical/major issue counts, a "Top issues" list (top 3 by impact, reusing `topIssues`
  ordering already computed in `scans.summary`), and a single link "View full report ↗"
  opening `/report/[scanId]` in a new tab (`text-adashi-blue hover:underline`, `target=
  "_blank" rel="noopener noreferrer"` — identical attributes to every other external link
  in this codebase).

**Article 14 block (D-6-12 — must be visually distinct, not just present):** rendered as
a bordered, non-editable block using the same `border-l-4` accent-bar convention already
established for the `CRITICAL` row treatment in `shortlist-table.tsx`, but in a neutral
tone so it does not read as an error: `border-l-4 border-gray-300 bg-gray-50 rounded-r-lg
p-3`. The 12px uppercase caption sits above the fixed notice text. It is never inside the
editable `<textarea>` — it is appended by code to what gets sent (D-6-12) and rendered as
a separate, read-only sibling block so "is it there" is answerable without reading the
draft body at all.

**Reject vs. Delete distinction:** Reject uses the same solid `bg-red-600 hover:bg-red-700
text-white` treatment as the existing bulk-delete button (visual weight signals real
consequence) but is a status write, not a row delete — the row does not disappear from
the table on reject, it moves out of the default pending filter into the "Rejected"
status filter, same as Approve moving a row into "Approved".
