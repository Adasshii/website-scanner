| Boundary | Description |
|----------|-------------|
| cron/admin caller → Postgres RPC | `batch_size` crosses from application code into a database function |
| prospect `website_url` → outbound fetch | untrusted third-party URL, stored earlier, re-used at scan time (handled in plan 04-03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of Service | `claim_next_scan_batch(batch_size)` | medium | mitigate | The function clamps its own argument with `least(greatest(batch_size, 0), 10)` so an oversized or negative batch_size cannot claim an unbounded set, independent of any caller-side validation (V5) |
| T-04-02 | Tampering | `prospects` writes | medium | mitigate | Migration 017 adds a CHECK constraint restricting `scan_status` to the four valid values; an invalid status is rejected at the database, not trusted from application code |
| T-04-03 | Denial of Service | shared Playwright capacity | high | mitigate | `RESERVED_FOR_PUBLIC` in `scanner-service/src/capacity.ts` keeps at least one slot permanently unavailable to bulk work, making SCAN-06 structural (D-08); asserted by `lib/scanner-capacity.test.ts` |
| T-04-SC | Tampering | npm install (`p-limit`) | high | mitigate | RESEARCH.md § Package Legitimacy Audit records the audit: `p-limit`, 298M weekly downloads, `github.com/sindresorhus/p-limit`, [SUS] only from a same-day patch publish date.
