<objective>
The tracer for Phase 7: one thin path from the existing marker columns, through the new
derivation, through an authenticated admin route, to five rendered funnel cards on a new admin
tab. After this plan Joshua can open the admin surface and see where every prospect actually
stands, which is success criterion 1 of the phase.

This is production-quality, not a prototype. It ships the complete 12-state derivation, the full
`x-admin-secret` guard, the real error and empty states, and the sent-gate honesty treatment.
What it defers is functionality, never architecture: the 30-day per-day table (plan 07-03), the
Shortlist column (plan 07-04), booking attribution (plan 07-05) and retention (plans 07-06,
07-07) all bolt onto the shape proved here.

Purpose: prove the read-side architecture end-to-end on one path before four more plans build
against it. `07-RESEARCH.md` flags the derivation ladder (Assumption A5) as the single
highest-leverage decision in the phase; getting it wrong silently misreports every prospect's
stage. The orchestrator has since CONFIRMED that ladder, so this plan implements it as a settled
decision.

Output: `lib/lifecycle.ts`, `lib/reporting-aggregates.ts`, `GET /api/admin/reporting`, a fifth
admin tab, and the held-out render test the UI-SPEC requires for its E1 backstop row.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/api/admin/reporting` | Untrusted HTTP request reaches prospect aggregate counts |
| Postgres -> Next.js server | `PostgrestError` objects and row data cross into the response path |
| server payload -> admin browser | Derived state and error detail render in the admin UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Spoofing | `GET /api/admin/reporting` | high | mitigate | Copy the `x-admin-secret` guard from `app/api/admin/outreach/route.ts:33-36` verbatim and place it before `createServerClient()` and before any query. Read-only is not a reason to skip it (ASVS V4). Asserted by a `curl` returning 401 on a wrong secret. |
| T-07-13 | Information Disclosure | reporting error banner interpolating `{detail}` | low | accept | The detail string is a `PostgrestError` message and can name a table or column. It reaches only an operator who already passed the admin secret, and this is the identical behaviour of the shipped `fetchShortlist`/`fetchOutreach` banners. Changing it here would fork the admin error convention for no gain. |
| T-07-14 | Tampering | `prospects.lifecycle_state` | high | mitigate | Phase 7 adds zero writers to that column. `lib/lifecycle.ts` reads it and only for the two terminal values, and `deriveLifecycleState()` short-circuits on `rejected` before any marker rung, making D-7-R2 structural. Asserted by the writer-count acceptance criterion in Task 1 and by the `rejected` unit test. |
| T-07-15 | Repudiation | funnel counts rendered as `0` while no send has occurred | high | mitigate | `sentGateOpen` is derived at read time from whether any `outreach_messages` row has ever reached `status = 'sent'`, and three of the five cards render the awaiting treatment while it is false. Enforced by the held-out render test in Task 2, not by code inspection, because the failure is silent (D-7-13). |
</threat_model>
