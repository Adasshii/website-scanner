<objective>
Put the fine-grained lifecycle state where Joshua already looks at individual prospects: a `Stage`
column on the existing Shortlist tab (D-7-14). One column, not a second list.

Purpose: plan 07-02 built `deriveLifecycleState()` and spent it on aggregate funnel cards, which
answer "how many are where". They cannot answer "which stage is *this* one stuck at". D-7-14 puts
that answer in the row Joshua is already reading, beside the `Status` column that reports the
bulk-scan queue state, and costs one column rather than a second surface.

Output: `ShortlistRow.stage`, resolved server-side inside `getShortlist()` with no extra query, and
a `StagePill` column rendered between `Status` and `Released`.

Why this plan sits at wave 3 behind 07-03 rather than beside it: it shares no file with 07-03, but
both carry `*.integration.test.ts` files that run against the one local Supabase instance.
`07-VALIDATION.md` § Test Infrastructure records that constraint explicitly (`fileParallelism:
false`, "do not run `npm test` in parallel shells"), and this project's standing convention is one
executor at a time. The dependency is on the shared database, not on anything 07-03 produces —
which is why this plan's `<context>` deliberately does not reference `07-03-SUMMARY.md`.
</objective>
