<objective>
Install the repo toolchain so every later Phase 9 plan starts from a green baseline, and ship the
ENG-07 enforcement guard: a static test that fails if any field Google returns is named in a write
path or in a Supabase schema column.

Purpose: D-9-R4 is a legal constraint (Maps Platform Terms section 3.2.3), and no Google call exists
anywhere in this phase. The guard ships now, before Phase 12 writes the first Google call, so that
phase inherits a rule that is already enforced rather than being trusted to respect prose. The
project has done this twice before (`lib/outreach-isolation.test.ts`, the retention table allowlist);
this is the third member of that family.

Output: `lib/google-content-guard.ts` (constants, two detectors, and the runtime
`toStorableGooglePlace` allowlist that Phase 12's single Google client must call) and
`lib/google-content-guard.test.ts` (the enforcement test).
</objective>

## Surfaced planner assumptions (spec-less edge-probe fallback)

This phase has no SPEC, so the deterministic edge probe ran in place of `## Edge Coverage`. Every
item came back `unresolved`. The item this plan owns is surfaced here rather than silently dropped.

- **ENG-07, `unclassified`** ("review manually"). The probe could not classify this requirement,
  so it stays unresolved. The planner's assumption, stated so it can be argued with: a *static*
  token-and-schema guard plus a *runtime* one-field allowlist is a sufficient enforcement pair for
  ENG-07 at this phase, because no Google call exists yet and the only thing that can be enforced
  today is the vocabulary and the schema. The assumption that is NOT covered: a future write that
  copies a Google response object wholesale, which no static token ban can catch. The control for
  that is assertion (c), which confines any Google endpoint call to one allowlisted file, plus
  `toStorableGooglePlace`, which Phase 12's client must call. If Phase 12 writes a Google call
  outside the allowlisted file, this guard fails; if it writes one inside it and spreads the raw
  object, this guard does not. That residual gap is recorded here deliberately.
</surfaced_planner_assumptions>
