<objective>
Build the own-site harvester and the pure parser that turn a loaded page into business facts as
structured data, with absence represented rather than merely absent.

Purpose: success criterion 2 asks that Joshua can read back from Supabase what the site publishes
AND which fields are missing. That makes the three-state field model load-bearing rather than
decoration, and the real measurement proves it: on 53 NL installer homepages, JSON-LD was present on
28, an address on 8, a telephone on 7, a service area on 5 and a credential on 2. Most fields will
legitimately come back missing. That finding is what the product sells.

Output: `types/own-site.ts`, the bounded browser-side `own-site-harvest.ts`, the pure Node-side
`own-site-facts.ts`, and two unit test files in the root vitest tree.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Prospect's page to the scanner's browser context | Every byte harvested is untrusted content from a site we did not write. |
| Browser context to the Node process | The harvest crosses this boundary as a serialisable value. Everything after it is parsing. |
| New scanner code to the existing scan | A throw in new code must not reach the existing `extractPageData` path that every public scan runs. |
