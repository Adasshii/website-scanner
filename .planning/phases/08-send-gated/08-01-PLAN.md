<objective>
Build the send gate: the schema that will hold the per-send audit record, the two counsel-supplied
config values that keep the gate shut, the gate evaluation that refuses a send, the opt-out link
that must live inside the copied body, and the Prepare action that runs all of it end to end.

Purpose: Phase 8's whole value is that a send is refused for a stated reason rather than allowed by
default. This plan builds the refusal machinery and proves it refuses. Nothing here can send
anything, and nothing here decides a legal question.

Output: migration 020, two new lib modules, one new admin route, one new button in the existing
review panel, and an integration suite that walks a real approved draft through the gate against a
real Postgres.

Implements these locked decisions from 08-CONTEXT.md:
- D-01: manual send, no third-party dispatch provider. This plan builds a gate and a renderer, never a mailer, and adds no mail dependency.
- D-05: both gates run at Prepare and refuse rather than warn. evaluateSendGates checks suppression against live state (CMP-02) and refuses a first-touch send when the Article 14 notice flag is not true (CMP-10).
- D-06: the opt-out is a plain body link into the Phase 2 unsubscribe endpoint, composed into the text that gets copied.
- D-07: no legal content is authored. Migration 020 leaves legal_regimes.legal_basis NULL and article_14_notice_approved false, and the acceptance-criteria grep gates fail the task if either is set.
</objective>

`evaluateSendGates` runs these checks in order and returns on the first failure. Every check refuses;
none warns:

1. Load the message with its embedded prospect through the existing foreign keys, selecting
   `id, prospect_id, status, draft_subject, draft_body, approved_by, prepared_at` plus

   Status must be exactly `approved`, else `not-approved`.
2. Query `send_records` for a row with this `outreach_message_id`; any hit is `already-sent`.
3. `contact_email` must be non-null and non-empty, else `no-contact-email`.
4. `contact_email_type` must be `generic` or `named-person`, else `contact-classification-unset`.
   A null classification cannot be recorded, so it fails closed rather than being guessed.
5. Call `isSuppressed()` from the Phase 2 suppression module against the resolved address. Capture
   the wall-clock timestamp of that call as `suppressionCheckedAt` and the boolean as

   never against anything cached at draft time (CMP-02).
6. Look up the `legal_regimes` row for `prospects.country`, selecting `legal_basis`,

7. `legal_basis` must be non-null and non-empty after trimming, else `legal-basis-unset`.
8. Compute `isFirstContact` as `true` when zero `send_records` rows exist for this `prospect_id`.

   `firstContactNoticeIncluded` to false. This is the CMP-10 enforcement point.
