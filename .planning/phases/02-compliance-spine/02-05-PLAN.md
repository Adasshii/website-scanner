## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Resend (external) → webhook route | Inbound events are only trusted after Svix signature verification (already present); suppression logic runs strictly after. |
| email_events (historical) → suppressions | The backfill reads system-owned data via the service-role client; operator runs it once from the deploy shell. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-16 | Spoofing | forged bounce/complaint event triggers a false suppression | high | mitigate | Existing Svix verification is unchanged; suppression runs only after `wh.verify` succeeds (Task 1) |
| T-02-17 | Tampering | recipient read from payload (undefined) silently skips suppression | medium | mitigate | Read recipient back from email_events via `.select("email")`; test asserts a row is created (Task 1, Pitfall 2) |
| T-02-18 | Repudiation | historical "stop" signals never enforced, contacting a prior complainant | high | mitigate | D-06 backfill over ALL bounced/complained rows, no email_type filter (Task 2, Pitfall 5) |
| T-02-19 | Denial of Service | an auto-suppress write failure breaks the transactional webhook's 200 ack | medium | mitigate | Suppression write is wrapped/logged and does not change the existing webhook response (Task 1) |
| T-02-SC | Tampering | new package supply-chain | low | accept | Zero new packages — reuses svix, tldts, supabase-js |
