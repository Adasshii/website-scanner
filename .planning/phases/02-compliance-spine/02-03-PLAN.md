<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| email recipient (untrusted) → unsubscribe route | The token in an inbound unsubscribe URL is attacker-controllable; only a valid HMAC signature over the server secret is trusted. |
| URL / server logs → PII | Tokens end up in access logs, Referrer headers, and mail-client link prefetch; they must not contain an email address. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08 | Tampering | forged token suppresses an arbitrary prospect | high | mitigate | HMAC-SHA256 over the payload with a server-only secret; verify before any write (Task 1 + Plan 04) |
| T-02-09 | Information Disclosure | timing side-channel on signature comparison | medium | mitigate | crypto.timingSafeEqual on equal-length buffers, never === (Task 1) |
| T-02-10 | Information Disclosure | email/PII leaked via the unsubscribe URL | high | mitigate | Token encodes only a prospect_id UUID; unit test asserts no email in payload (Task 1) |
| T-02-11 | Denial of Service | malformed token crashes the verifier | low | mitigate | verifyUnsubscribeToken returns null on any malformed/parse error, never throws |
| T-02-SC | Tampering | new package supply-chain | low | accept | Zero new packages — Node stdlib crypto only |
</threat_model>
