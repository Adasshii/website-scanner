<helper_contract>
Both helpers are written from this one contract and then stay separate forever: the scanner
service is the always-on Railway process, the drafting runs on Vercel. Neither imports the other.

Exported surface, identical in `scanner-service/src/llm.ts` and `lib/llm.ts`:

- `LLM_MODEL` — the model id string.
- `LLM_EFFORT` — the single `output_config.effort` value, one constant per helper so cost is
  tunable in one place.
- `LLM_MAX_TOKENS` — 16000.
- `LlmRefusalError` — an Error subclass thrown on a refusal stop reason.
- `hasLlmKey(): boolean` — true when `ANTHROPIC_API_KEY` is set. Reads `process.env` directly,
  never caches the boolean, never exports the value.
- `generateContent(options): Promise<string>` where options are
  `{ prompt: string; json?: boolean; image?: { base64: string; mediaType: string }; maxTokens?: number }`.

`generateContent` behaviour:

1. Lazily build a module-scope client singleton. Throw when the key is absent — callers gate on
   `hasLlmKey()` first, exactly as they gated on the old nullable client.
2. Build the content array: when `image` is present, the image block first and the text block
   second; otherwise the text block alone.
3. Normalise `image.mediaType`: lowercase, cut anything from the first `;`, trim, and clamp to
   the four allowed types, falling back to image/jpeg.
4. Call `client.beta.messages.create` with the betas array, `fallbacks: "default"`,
   `output_config: { effort: LLM_EFFORT }`, `max_tokens: options.maxTokens ?? LLM_MAX_TOKENS`,
   one user message, and nothing else.
5. If `stop_reason` is the refusal value: log one distinct line naming the model and the
   refusal, then throw `LlmRefusalError`. Never fall through to the text path.
6. Extract text by filtering the content union for text blocks, joining their `text` with a
   newline, and trimming.
7. When `json` is true, strip a wrapping markdown fence if present, then return the outermost
   JSON object or array (whichever opener appears first, matched to its last closing bracket).
   If no object or array is found, return the trimmed text unchanged so the caller's existing
   `JSON.parse` throws into its existing catch, exactly as it does today on garbage.
8. Let SDK errors propagate. Every caller already sits inside a try/catch that logs and returns
   a fallback; that is the invariant the whole AI layer in this codebase is built on.

The `json` and `image` options exist in both helpers for contract parity even though the Next
side uses neither today. Say so in a comment at the option type.
</helper_contract>
